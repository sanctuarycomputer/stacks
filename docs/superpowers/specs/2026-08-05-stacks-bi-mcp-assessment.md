## 1. How admins actually use Stacks (the surfaces to mimic)

Nine BI surfaces, in rough frequency-of-use order:

1. **Collective dashboard** (`/admin/dashboard`): 8 YTD OKR tiles (hardcoded to accrual; g3d profit-margin & growth tiles, per-studio successful projects/proposals) with a `growth_progress` pro-rating shape, plus **Money at a Glance**: net cash (live QBO account balances, Bank+CC−Liabilities), 3-month average burn (COGS+Expenses from the P&L cache), per-account balance table, New Deal balances. 24h-cached.
2. **Studio health** (`/admin/studios/:id`): the OKR **grid** (rows = every OKR incl. synthetic Profit/Surplus Profit; columns = periods; cells = value/target/tolerance/health/surplus/hint) + 5 Chart.js panels (profitability, growth+trendline, economics, new-biz, utilization stacks). Knobs: gradation ×7, cash/accrual, period count.
3. **Enterprise health** (`/admin/enterprises/:id`): per-legal-entity burn, net cash, **runway = net_cash / avg_burn** ("3–6 months is healthy") — the only runway computation in the app — plus a **verticals** axis (`[SC]`-style account tags) and profitability/growth charts.
4. **Project tracker show**: the **budget burn-up** (Chart.js: flat budget-low/high lines + cumulative Income (by invoice due-date), Spend (daily, from snapshot), Cost (monthly COSR, from snapshot)); the money table (invoiced / running / total spend, at-budget & over-budget overage); **estimated completion** (weeks/months of budget left at trailing 7/30-day spend); per-workstream hours×rates; contributors with role periods; capsule/success status.
5. **Project cost explorer**: `monthly_cosr` — per-person per-month cost (salary pro-rata + contributor payouts).
6. **OKR explorer**: per-OKR evidence drill-downs (per-tracker margin/free-hours/satisfaction rows; per-lead proposal outcomes; the per-person rate→hours utilization table).
7. **Per-person key metrics**: skill-band points + individual utilization/sellable ratios.
8. **Quarterly report** (`/admin/periodic_reports`): collective OKR chips + the profit-share **blueprint** (gross surplus, pool, per-contributor shares/multipliers/amounts, acceptance).
9. **Money → payable QBO bills**: the AP view (per-realm unpaid bills). Plus `/admin/tasks` (already exposed via `list_open_admin_tasks`).

## 2. The data reality

- **The P&L cache is the only financial substrate** — exactly as Hugh framed it. `qbo_profit_and_loss_reports` stores `{cash: {rows: [[label, "value"]]}, accrual: {…}}` per (realm, range), re-synced nightly from 2023-01-01 forward, monthly+quarterly+yearly. All hierarchy is flattened; structure survives only as row order and two **coexisting label conventions**: `[SC] Account` (Enterprise verticals) vs `Account - PREFIX` (Studio attribution).
- **Derived caches on top:** `Studio#snapshot` (7 gradations × periods × {cash,accrual} × ~30 datapoints + okrs + per-person utilization) and `Enterprise#snapshot` (verticals × {cash,accrual} × 4 datapoints) — *different schemas, different income definitions* (Studio `income`/`Net Operating Income` vs Enterprise `revenue`/`Net Income`). `ProjectTracker#snapshot` carries the full burn-up series (cumulative daily spend, daily hours, monthly cost, invoiced totals).
- **OKRs**: single-KPI rows (name/operator/datapoint) + per-window target/tolerance applied to studios; health = 4-band symmetric-tolerance grading; compounding-rate operators rescale to period length; the quarterly snapshot **feeds profit-share payouts** (`successful_projects` multiplies the pool).
- **Genuinely absent from Stacks**: balance sheet, cash-flow statement, persisted bank balances, persisted chart of accounts, AP aging buckets, vendor-spend aggregation, per-line expense detail (table dropped in 2022). Net cash today comes from **live QBO calls** on page render. The report fetcher (`ReportsJSON`, report name as an argument) is trivially generalizable to `BalanceSheet` / `CashFlow` / `AgedReceivables` / `AgedPayables` — that's the unlock for true financial *position*.

## 3. Existing MCP surface (12 read + 13 write tools)

High-fidelity: `get_studio_health` (snapshot pass-through, deliberately strips per-person utilization), `list_open_admin_tasks`, `get_ar_aging`/`list_overdue_invoices` (derived AR), `get_resourcing_projections` (live Runn). Partial: `list_projects_at_risk` (verdicts, no series), `list_project_trackers` (thin). Write surface is provisioning/projection-only by design. House conventions: `Responses.ok/error`, per-row rescue-and-skip, literal-enum errors listing valid values, decimals→Float, param clamping, never echo internals.

## 5. Tier 2 — small Stacks engineering (new syncs; the position unlock)

1. **`sync_balance_sheet!` + `get_balance_sheet`** — generalize `fetch_profit_and_loss_report_for_range` (report name is just an argument) into a `qbo_reports`-style store keyed by report type; nightly per realm. Gives true per-entity position: assets/liabilities/equity, **persisted bank balances** → `get_cash_position` (net cash + runway from cache, replacing the live-call path) — Hugh's "financial position of each entity", properly.
2. **Persist the chart of accounts** — `fetch_all_accounts` → nightly table (an `accounts_cache` service already exists); `get_chart_of_accounts` per entity with balances and classifications.
3. **Optional**: `AgedPayables`/`AgedReceivables` report syncs (native QBO aging replaces the hand-rolled AR bucketing; adds AP aging which doesn't exist at all today).
4. `list_pipeline` (unchanged from the July spec — Notion-lead mirror per studio/period; unblocks Business pre-read).

## 6. Supersedes / defects / hazards

- **ROADMAP correction:** P1a's `get_pnl`, `get_kpis`, `get_chart_of_accounts` entries (added 2026-08-04) are superseded: MoM KPI series already exist inside the Studio/Enterprise snapshots (the new tools expose them); raw P&L is subsumed by `get_enterprise_health` (+ a `raw_rows: true` param if line-level detail is ever wanted); chart-of-accounts moves to Tier 2 with a sync.
- **Defects found (fix en route):** D1 Enterprise snapshot `profit_margin` always 0 (computed-but-never-assigned, two sites); D2 `find_rows` called with a String → substring matching (works by luck); D3 latent arity bug in `key_datapoints_for_period` default args (trips any live caller); D4 five OKR datapoint enums have no producer (nil-deref if an admin creates one); D5 dead first assignment of enterprise `profitability_data`.
- **Hazards (design constraints):** H1 read the caches only — never `find_or_fetch_for_range` (live QBO + `delete_all` on force) and never bulk `QboInvoice#data` (lazy per-row live fetch); H2 `Stacks::Period#report` without an explicit `qbo_account` silently returns **Sanctuary** — every finance tool threads the realm explicitly and echoes the entity; H3 `QboBill#destroy` deletes the remote bill; H4 Enterprise-vs-Studio schema/label differences must never be presented as the same number; H5 studio pre-2023 periods fall through to live QBO (period floor mismatch).
- **In-flight work to reconcile first:** worktrees `mcp-capacity-pnl` (name suggests overlapping tool work) and `optimizations` (extracts `okrs_for_period` → `Studios::Snapshots::OkrRows` service — tool code should target whichever survives).
